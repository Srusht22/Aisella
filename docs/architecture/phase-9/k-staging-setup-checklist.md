# K. Staging setup checklist (owner condition 9)

**Rules:**
- **Secret values are never written in chat, issues, documents or the repository.** The owner enters them directly into the cloud environment's settings, the Supabase dashboard, or a file outside the repository (mode 600).
- The assistant only checks that a named variable is **present**, and never prints it.
- **Nothing here is executed until the owner explicitly authorizes the staging deployment and the first channel.**

## 3. Steps (after authorization)

1. Create A1–A7. Set a spend limit (budget alert and quota) on the Gemini API project.
2. Apply the migrations to staging (`supabase db push`). Set the role passwords in the SQL editor.
3. Set the function secrets from a file outside the repository (`supabase secrets set --env-file …`).
4. Deploy `ai-assist`, `channel-webhook`, `channel-send` and `channel-oauth`.
5. Register the webhook URL and verify token in the Meta app. Subscribe to the `messages` field.
6. Run the preflight, extended for the channel roles. Everything must pass, and no secret value may appear in its output.
7. Connect the seller test account through OAuth. Confirm the "Connecting" → "Connected" round trip.
8. Run the scripted test with the two team accounts ([G §3](g-test-plan-and-staging.md#3-staging-integration-test-later-needs-approval)):
   - inbound;
   - opt-in suggestion;
   - "Use this reply" → Send;
   - echo matched;
   - a forged webhook rejected;
   - a replayed webhook deduplicated;
   - disconnect.
9. Check the function logs: no message text and no tokens.
10. Record the results; revoke or rotate the test tokens if they will not be reused.

**Known constraint:** WhatsApp sends some webhooks only in Live mode ([I W11](i-official-verification.md#1-whatsapp-business-platform)). For the Instagram path, development mode with role accounts is the confirmed sandbox.
